Securing SSH: Beyond Port 22

Ed25519, MFA via Google Authenticator, Fail2Ban, and Port Knocking. A comprehensive guide for bulletproof remote access.

sshd_config

# Hardened SSH daemon configuration

Port 42123

AddressFamily inet

ListenAddress 0.0.0.0

PermitRootLogin no

PasswordAuthentication no

PubkeyAuthentication yes

KbdInteractiveAuthentication yes # Required for PAM MFA

AuthenticationMethods publickey,keyboard-interactive

Introduction

Opening port 22 to the Internet guarantees thousands of bruteforce (dictionary) attempts every hour. Historically, changing the port was enough for "Security by Obscurity", but with massive scanners like Shodan or Zmap, an obscure port is no longer a sufficient barrier.

Step 1: Ed25519 Asymmetric Keys

RSA 2048 (and even 4096) is heavy and aging. The Ed25519 elliptic curve offers a very high level of security with a short key size and ultra-fast performance.

ssh-keygen -t ed25519 -C "admin@portfolio"

Step 2: MFA via TOTP (Google Authenticator)

Even if your private key is stolen or extracted, a Time-based One-Time Password (TOTP) will block access. Simply install the PAM module (Pluggable Authentication Modules).

sudo apt install libpam-google-authenticator
google-authenticator

The module will create a QR Code to scan with your mobile app. Then edit `/etc/pam.d/sshd` to require it.

Step 3: Fail2Ban

Fail2Ban reads the history of `/var/log/auth.log` in real-time. If it detects more than X failed attempts from the same IP, it automatically creates a firewall rule (iptables) that bans the attacker for a specified duration. Mandatory on any publicly exposed server.
