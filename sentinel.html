Sentinel Drop Box v2.0

A hardware and software probe designed for security audits and Red Teaming operations. Fully autonomous in power and decision-making for stealthy surveillance or active vulnerability reconnaissance on air-gapped networks.

Project Concept & Comparison with Standard Setups

During red teaming and security audits, physical entry is sometimes the only viable entry point. Standard audits typically require deploying a bulky Kali Linux laptop, which is highly conspicuous, or using expensive custom appliances that lack flexible inline redirection.

Project Sentinel v2.0 is a custom, fully integrated "Drop Box" probe. It is designed to be physically deployed behind a target's workstation or VoIP phone to conduct stealthy network surveillance or active scanning:

  • Stealth Bypass Interception: Operates inline between the client device and the router, duplicating traffic transparently without raising link-state alerts.
  • Bilingual Network Persona: Operates fully out-of-band, offering a hidden wireless management access point for the auditor while running a isolated physical interface on the target network.
  • Autonomous Multi-Mode Logic: Transitioning between passive sniffing and active vulnerability correlation automatically or via physical control interfaces.

Hardware Adaptations: Taming the Raspberry Pi 3A+

Operating a hardware drop box in the field introduces strict constraints on power draw, hardware conflicts, and time synchronizations on offline systems. The following custom solutions were built to address these bottlenecks:

> 1. Power Optimization: The Raspberry Pi 3A+ Advantage

A standard Raspberry Pi 3B+ draws around 500mA–1.2A+ due to its onboard USB hub and Ethernet controller chip. To maximize battery life, a Raspberry Pi 3A+ was chosen. Since the 3A+ lacks these power-hungry integrated circuits, it cuts power consumption in half (drawing only 200–300mA under load), extending deployment autonomy.

> 2. Inline Interception (Netgear Switch & Step-Up 12V Cable)

To sniff network packets without interrupting the connection of target devices, the probe utilizes a compact Netgear managed switch configured for Port Mirroring (SPAN). To power both the Pi (5V) and the switch (12V) off a single standard 5V USB power bank, a custom Step-Up voltage converter cable was engineered, allowing inline deployment with a single battery.

> 3. Forensic Timekeeping (DS3231 RTC Module)

As the drop box operates offline on air-gapped target networks, it cannot sync system time via NTP. When it boots, the system time defaults to the Unix epoch, which corrupts PCAP packet timestamps. To resolve this, a physical DS3231 RTC module was connected to the I2C bus (0x68), guaranteeing accurate timestamping for forensic packet analysis.

> 4. Tactical Interface Bus Sharing (OLED Display & RTC)

To check IP configuration and system health in the field without connecting a computer, a 0.96" OLED screen was added. To prevent GPIO pin exhaustion, the screen and the RTC module share the same physical I2C bus. The Linux kernel configuration (/boot/config.txt) was adjusted to support both addresses (0x3C and 0x68) simultaneously.

Software Architecture and Core Features

> 1. Out-of-Band Network Stack Isolation

To guarantee stealth, the target-facing USB-Ethernet adapter (eth0) is isolated. Standard DHCP requests are silenced, and Debian's wpa_supplicant service is completely masked to prevent the device from attempting to connect to corporate Wi-Fi. Management access is handled out-of-band by transforming the internal Wi-Fi (wlan0) into a hidden Access Point via hostapd and dnsmasq.

> 2. Multi-Mode Security Orchestration (switch.sh)

The system behavior is governed by a custom bash orchestrator (switch.sh) which manages iptables rules, network interface modes, and scanning daemons. It allows switching dynamically between passive listening, active scanning, and database vulnerability enrichment.

> 3. Memory-Efficient Sniffing & Storage Guard

Passive sniffing (Mode 1) is handled by a Python Scapy daemon. Since the Pi 3A+ is limited to 512MB RAM, the capture writes packets directly to the SD card in real-time (using Scapy's store=0 flag) to prevent memory saturation. A background thread monitors storage space, automatically halting captures at 90% disk utilization to prevent filesystem corruption.

CLI Command Reference

The orchestrator is controlled via command-line arguments on the out-of-band SSH session:

switch.sh --mode passive — Activates promisc mode on eth0 and starts Scapy sniffer daemon.

switch.sh --mode active — Exits stealth mode, runs local ARP/ICMP sweeps and SYN port scans.

switch.sh --mode enrich — Reads offline scan results, connects to NIST API and correlates CVEs.

switch.sh --status — Displays current battery charge, CPU temp, and target link state.

Project Highlight: Project Sentinel demonstrates complete mastery of the offensive pipeline: from physical hardware engineering (power conversion, I2C routing) and Linux systems administration to advanced network automation scripting in Python.
