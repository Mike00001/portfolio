Preamble

Suricata is an Open Source threat detection (IDS) and intrusion prevention (IPS) engine. Unlike Snort, it is natively multi-threaded, making it ideal to leverage the 4 cores of a Raspberry Pi.

1. IPS mode configuration (NFQ)

For Suricata to block (Drop) a packet instead of just alerting, it must intercept the traffic. On Linux, this is done via NFQUEUE (Netfilter Queue).

# Redirect all incoming/outgoing traffic to queue 0
sudo iptables -I INPUT -j NFQUEUE --queue-num 0
sudo iptables -I OUTPUT -j NFQUEUE --queue-num 0
sudo iptables -I FORWARD -j NFQUEUE --queue-num 0

Then, edit the /etc/suricata/suricata.yaml file to indicate the NFQ execution mode.

2. Managing False Positives

Enabling all IPS rules will block many legitimate services. It is essential to tweak the rules file (`modify.conf` for `suricata-update`) by changing non-critical network alerts to simple detection without blocking.

Warning: If Suricata crashes in NFQ mode, all your network traffic will be blocked because packets redirected to Netfilter will not find any application to accept them. Have a fail-safe script ready to flush iptables if the suricata service goes down.
