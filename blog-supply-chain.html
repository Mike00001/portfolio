Threat Intel Supply Chain

The rise of supply chain attacks

How SolarWinds and NPM attacks transformed our approach to implicit trust in third-party code.

Historically, when a company wanted to secure its infrastructure, it installed firewalls, NDR/EDRs on endpoints, and created an impenetrable defense perimeter. But what happens when the enemy doesn't force the front door, but is invited inside, disguised as a valuable security update?

The SolarWinds textbook case

The SolarWinds Orion attack (late 2020) will go down in history. Attackers (APTs, most likely based in Russia) compromised SolarWinds' code repositories. As a result, every time a customer downloaded an Orion update, it was digitally signed using valid SolarWinds certificates, but it embedded the Sunburst malware.

"A supply chain vulnerability is a security nightmare because it de facto bypasses the implicit trust model: the update comes from the publisher, therefore I accept it."

The Open Source world is not spared

More recently, package registries (NPM for Node.js, PyPI for Python, or RubyGems) have become prime targets. The methods are numerous:

  • Typosquatting: Placing malware in a package named reqeusts instead of requests. Rushed developers fall into the trap.
  • Dependency Confusion: Pushing a fraudulent package onto a public repo with the same name (but a much higher version) as a private internal company component. The package manager will prioritize downloading the internet version.
  • Maintainer Compromise: Stealing a legitimate developer's NPM token and pushing an infected update to a package with 10 million weekly downloads.

Conclusion: The Zero-Trust Model

There is no magic solution, but concrete mitigations are emerging: the creation of SBOMs (Software Bill of Materials) to have a complete inventory of software components, signing commits via GPG, and implementing a Zero-Trust approach, even for internal dependencies.
