A modular security daemon written in Bash and Python designed to monitor Linux endpoints. It audits user activity, validates file integrity, and isolates suspicious network connections and processes.

Project Concept & Comparison with Standard HIDS

Host-based Intrusion Detection Systems (HIDS) like Wazuh or OSSEC are powerful defensive tools, but they require heavy database backends, centralized managers, and significant system memory. This overhead makes them impractical for low-spec cloud micro-instances, Docker containers, or minimal IoT gateways.

Host Intrusion Detection System (HIDS) is a modular, zero-dependency endpoint monitoring agent. Written in Bash and Python, it operates directly on host system assets and outputs structured JSON alerts:

  • Native POSIX Auditing: Relies exclusively on core Unix system calls and commands.
  • Proactive Path Auditing: Actively flags transient directory executions and masqueraded process names.
  • Compact Integrity Loops: Watches crucial authentication files and system configurations.

System Hardening & Core Resource Optimizations

Running an audit agent continuously on production hosts requires minimizing CPU and I/O cycles:

> 1. Zero-Dependency Footprint (POSIX Commands)

The agent is designed to execute on stripped-down Linux installations, using built-in POSIX utilities (like ps, ss, and readlink).

> 2. Systemd Service Sandboxed Integration

The modules are packaged as system daemons managed by systemd (with ProtectSystem=full and PrivateTmp=true).

> 3. Low-I/O File Integrity Monitoring (FIM)

The FIM daemon hashes and watches specific critical databases (like /etc/passwd and /etc/shadow).

Software Architecture and Code

# Trace and validate executables
ps -eo pid,user,comm,%cpu,%mem --no-headers | while read pid user comm cpu mem; do
    exe=$(readlink -f /proc/$pid/exe 2>/dev/null)
    [ -z "$exe" ] && continue

    # Flag execution from transient paths
    if echo "$exe" | grep -qE "/tmp|/dev/shm|/var/tmp"; then
        msg="Process $comm (PID $pid) executing from transient directory: $exe"
        write_alert "CRITICAL" "$msg"
    fi
done

CLI & Log Output Reference

systemctl start hids-audit.service — Starts HIDS daemon.

tail -f /var/log/hids/alerts.json — Accesses raw JSON alert stream.

Project Highlight: HIDS offers lightweight, zero-dependency host auditing, providing defensive visibility for micro-instances, containers, and IoT gateways with near-zero performance footprint.
